# Sync the public GitHub README with accepted ChatMD state

## Outcome

Bring the public GitHub README in sync with the currently accepted ChatMD
product state.

A technically capable stranger should understand what ChatMD is, how to run
it, what it produces, and what it does not yet provide, without first reading
CHAT-1 through CHAT-5.

## Governing authority / source of truth

CHAT-P1 defines the product purpose, capture boundary, and no-rewrite
invariant.

Accepted CHAT-1 through CHAT-5, together with the current `chatmd.py` and
`test_chatmd.py` implementation, are the technical source of truth for what
ChatMD actually does today.

CHAT-D1 remains the unresolved portable bundle contract. It must not be
described as implemented.

This Work does not reopen CHAT-5.

## Scope

Rewrite `README.md` as a polished GitHub landing page that accurately
describes the current one-URL capture workflow:

- public ChatGPT share fetching and structured-share parsing;
- active visible conversation reconstruction;
- deterministic Markdown serialization;
- local vault capture under
  `/Users/marwan/My vault/Sources/ChatMD/YYYY/MM/`;
- collision, contentless-export, failure, and `Saved:` path semantics;
- current image and file placeholder behavior;
- machine-specific capture root and unpackaged CLI status.

Keep the README concise and external-facing. Point interested readers to
`authority/Projects/CHAT-P1/` without turning the README into LWA
documentation.

## Non-goals

Do not:

- modify product code or tests;
- reopen CHAT-5;
- implement packaging, capture-root configuration, image downloading, or
  the CHAT-D1 bundle contract;
- invent capabilities, install commands, or distribution status;
- change Project, Document, or prior Work contracts beyond the navigation
  generated by render.

## Evidence requirements

- Every material README capability claim is checked against current
  `chatmd.py`, `test_chatmd.py`, and accepted CHAT-1 through CHAT-5
  authority.
- Stale CHAT-2-era claims are removed rather than carried forward.
- `git diff --check` passes for the intended docs and authority diff.
- Local-native render and validate succeed after this Work is added.

## Acceptance criteria

- [x] `README.md` describes the current accepted capture workflow rather
      than the pre-serialization parser-only state.
- [x] The README states how to run ChatMD from this repository with

      form.
- [x] The machine-specific capture root
      `/Users/marwan/My vault/Sources/ChatMD/YYYY/MM/` is explicit.

- [x] No unimplemented bundle, packaging, or knowledge-processing capability
      is described as available.
- [x] Product code and tests are unchanged.
- [x] `git diff --check` and local-native render/validate pass.
